# פיצול PR #305 לתקרת ה-auto_merger (Refs #335, Refs #305)

`auto_merger` ממזג רק PR-ים של עד 400 שורות שונות (תוספות + מחיקות).
GitHub מציג ל-PR #305 — `factory/laptop-claude-263-sync-9` → `main`, מסירה
9/19 של הסנכרון `master` → `main` — **590 שורות**, ולכן הוא נחסם.

## למה 590, והאמת היא 331

| מה נמדד | פקודה | שורות | קבצים |
| --- | --- | --- | --- |
| מה ש-GitHub וה-auto_merger מודדים | `git diff --shortstat origin/main...origin/factory/laptop-claude-263-sync-9` | **590** | 17 |
| מה שבאמת חסר ב-`main` | `git diff --shortstat origin/main..origin/factory/laptop-claude-263-sync-9` | **331** | 8 |

ההפרש — 259 שורות — הוא **בדיוק** מסירה 8, שנחתה ב-`main` כ-squash (#304).
הענף של מסירה 9 בנוי מעל מסירה 8, ולכן הקומיטים שלה עדיין בהיסטוריה שלו,
נקודת הפיצול (`merge-base`) נשארה ב-`cfe47b7` (#303), ואותן 259 שורות נספרות
פעם שנייה. 331 + 259 = 590. אותה מלכודת בדיוק שתוארה ב-
[`PR-300-SPLIT.md`](PR-300-SPLIT.md) — שם מסירה 4 הוצגה כ-513 במקום 228.

ו-`main` ומסירה 8 **זהות בתוכן**:
`git diff origin/main origin/factory/laptop-claude-263-sync-8` ריק לגמרי. אין
כאן שום הכרעה ידנית ואפס סיכון לקונפליקט.

מהיום יש לזה פקודה אחת, `tools/pr-size.js`, שמודדת את שתי הספירות ונותנת
הכרעה:

```

אין מה לפצל — נקודת הפיצול מיושנת: מוצגות 590 שורות אבל חסרות רק 331. למזג את היעד לענף ולמדוד שוב.
```

## הדרך הזולה: לסנכרן את הענף, לא לפצל

331 שורות הן מתחת לתקרה. מספיק להזיז את נקודת הפיצול:

```sh
# אפשרות א׳ — לעדכן את ה-PR הקיים (עדיף: ה-PR, הדיון והביקורת נשמרים)
git switch factory/laptop-claude-263-sync-9
git merge origin/main          # ללא קונפליקטים: main ומסירה 8 זהות בתוכן
npm test
git push
```

ואחרי המיזוג GitHub יציג 331 וה-auto_merger יוכל למזג — **אחרי** שמתקנים את
המוג׳יבקה שלמטה, שהיא חוסם אמיתי ולא עניין של גודל.

### למה לא שלושה חלקים

החלוקה «מתבקשת» היא שלושה: הבנק (66 שורות), המודול + החיווט (226) והישר
(39). היא **לא עובדת** — המודול לבד נכשל:

```
not ok 173 - banks contains Grade א music items for skip counting, 100-chart, patterns, and scale jumps
```

`test/grade1Music.test.js` בודק גם את הבנק (`banks.ST.CHART100`,
`banks.ST.PATTERN`, 12 פריטים בכל אחד), ולכן המודול והבנק חייבים להיות באותו
PR. בכיוון השני, בלי שורת ה-script ב-`index.html` נופל

```
not ok 347 - every src/lib module is loaded by a page or listed as intentionally unused
```

(`test/reachability.test.js`), ושורת ה-`sw.js` הולכת איתה כדי ששתיהן יישארו
מסונכרנות — `test/pwa.test.js` דורש שכל סקריפט שדף טוען יהיה ברשימת
ה-precache. חלק 1 הוא היחידה הקטנה ביותר שעומדת בפני עצמה.

הבנק באמת מגיע לילד: שלושת המפתחות החדשים יושבים על `skill` שכבר ב-
`GRADE_SKILLS['א']` (`counting`, `number_line`), ו-`allItems()` עולה מ-637
ל-685 — כל 48 הפריטים עוברים את `isShippable` (12 `CHART100`, 12 `PATTERN`,
12 מקצב, ו-`number_line` מ-18 ל-30).

הגרסה של `master` תגיע בסנכרון הבא.

## הערת ביקורת: `scaleStepFreq` מוגדר פעמיים

חלק 1 וחלק 2 מגדירים שניהם `scaleStepFreq` — אחד ב-`grade1Music.js` ואחד ב-
`numberLine.js` — ושני המודולים עושים `Object.assign(root, api)` בדפדפן.
ב-`index.html` תג ה-script של `grade1Music.js` בא אחרי `numberLine.js`, ולכן
הגרסה של `grade1Music` דורסת את זו של `numberLine` ב-`globalThis`. הגוף של
שתיהן זהה (`Math.round(f * Math.pow(2, j / 10) * 100) / 100`, ברירת מחדל 220),
אז התנהגותית זה שקול — אבל זו בדיוק מלכודת ההצללה ש-`node --test` לא רואה,
כי ב-Node כל מודול נטען דרך `require` משלו. בגרסה של `master` זה כבר מתוקן
בדרך הנכונה: `grade1Music` מאציל ל-`numberLine` ולא מעתיק.
