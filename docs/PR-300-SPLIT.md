# פיצול PR #300 לתקרת ה-auto_merger (Refs #323, Refs #300)

`auto_merger` ממזג רק PR-ים של עד 400 שורות שונות (תוספות + מחיקות).
GitHub מציג ל-PR #300 — `factory/laptop-claude-263-sync-4` → `main`, מסירה
4/19 של הסנכרון `master` → `main` — **513 שורות**, ולכן הוא נחסם.

## למה 513, והאמת היא 228

ה-513 הן ארטיפקט של ענפים מוערמים, לא גודל אמיתי:

| מה נמדד | פקודה | שורות |
| --- | --- | --- |
| מה ש-GitHub מציג (דיף מנקודת הפיצול) | `git diff --shortstat origin/main...origin/factory/laptop-claude-263-sync-4` | **513** |
| מה שבאמת חסר ב-`main` | `git diff --shortstat origin/main origin/factory/laptop-claude-263-sync-4` | **228** |

הענף של #300 בנוי מעל `sync3`, ו-`sync3` נחת ב-`main` כ-**squash** (#299).
כלומר התוכן של מסירה 3 נמצא ב-`main`, אבל הקומיטים שלה עדיין בהיסטוריה של
#300 — ולכן נקודת הפיצול (`merge-base`) נשארה ב-`0e614ac`, לפני #297–#299,
ו-285 השורות של מסירה 3 נספרות שוב. 285 + 228 = 513.

מעבר לשורות שנספרות פעמיים, `main` ו-`sync3` **זהים בתוכן**
(`git diff origin/main origin/factory/laptop-claude-263-sync-3` ריק) — אין
כאן שום הכרעה ידנית וגם אפס סיכון לקונפליקט.
